# Offline campaign integration result

2026-09-20. No hardware commands, device connections, firmware installation or
settings changes. This is native fake-bus integration with real host file exports.

## Implemented test path

Extended the existing composition test bridge rather than creating another
executor. Each run uses the real native composition, authentication, preparation,
campaign owner, evidence store and route handlers with a deterministic fake bus.

1. Native preparation publishes a signed challenge.
2. Python verifies the response and signs the exact campaign admission.
3. The authenticated native start route accepts the admission.
4. Native polling executes one bounded fake-bus leg and waits for export.
5. Existing record-info/chunk routes transfer the result, with each response
   signature verified by the Python test bridge.
6. Existing `RecordTransfer` checks size, order and final digest.
7. Existing `CharacterizationHostSession` exports raw/readable data, independently
   assesses it and signs a receipt only after successful verified publication.
8. The native receipt route accepts it; the next leg reacquires its baseline.
9. After the twelfth receipt, state is COMPLETE, fake writes total twelve and the
   retained evidence buffer is released.

## Outcomes

| Scenario | Outcome |
| --- | --- |
| Legacy pattern | 12 legs, 12 verified disk exports, 12 accepted receipts, COMPLETE |
| Matched-target pattern | 12 legs, 12 verified disk exports, 12 accepted receipts, COMPLETE |
| Matched pattern, disk-export failure at leg 4 | Host latches failure without receipt; native export deadline faults; exactly 4 fake writes, no fifth |

The fake bus injects constant +9/-7-count residuals. Outcomes remain SETTLED_MISS;
the tests do not relabel them accurate. They demonstrate eligible bounded-miss
progression through this offline campaign policy, not physical motion quality.

During test construction, the request sequence initially jumped to 100. The
authentication gate correctly rejected it. The bridge now maintains contiguous
request sequence numbers across status polling and record transfers; policy was
not weakened to accommodate the test.

## Reproduce

From `software`:

```powershell
..\.venv\Scripts\python.exe -m pytest tests/unit/test_characterization_composition.py -q
```

The six composition tests include both signed admissions, both complete campaigns
and the export-failure stop scenario. Exports are isolated pytest temporary files,
not historical hardware evidence. The tests require the local native compiler.
The broader composition, host-session, transfer, result-codec and request-auth
regression run passed all 29 focused tests.

## Limits and next step

- Test bridge calls native route handlers in-process; it does not exercise real
  TCP, Wi-Fi delays or the complete physical-board firmware image.
- Request signatures are generated by the native fixture; response verification,
  campaign signing, record assembly and result receipts use the real host code.
- Fake time advances deterministically. This does not validate real export latency
  against controller deadlines, servo load, mechanical clearance or tip accuracy.
- Existing ESP32 compile probe is compatibility evidence, not a deployable image
  or a full runtime memory measurement.

Next: integrate the existing host HTTP/session components into one finite offline
workflow using the same contracts, including uncertain-response/disconnect tests.
Then review board composition, resource/timing budgets and release provenance
before considering physical deployment. Do not add another campaign protocol.
