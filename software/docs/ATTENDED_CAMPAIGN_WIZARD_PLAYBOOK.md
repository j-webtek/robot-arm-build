# Attended two-endpoint wizard playbook

## What is available

The existing physical-mode wizard has a **Run two attended wrist endpoints**
action. It connects to the native campaign owner, which uses one USB serial
connection for at most two wrist commands with baseline and endpoint telemetry.
The final action is available after trusted-host configuration, not automatically
merely because a USB device is visible.

No new browser endpoint accepts raw motion commands, arbitrary file paths,
controller bindings or approval signatures. Existing operator actions and
single-use tickets remain the interface for Start and cancellation.

## Host setup contract

Newly staged campaigns use intent v3. This changes storage capacity only:
16 KiB baseline plus 80 KiB post-command capture per leg (96 KiB maximum),
192 KiB across two legs. The five-second post window, read-count limits,
deadlines, nominal commands, speeds, endpoint tolerances and fault holds are
unchanged. Existing v1/v2 originals retain their original 48 KiB post limit;
never relabel an old request or reuse its signature. Over-capacity still holds
the campaign and preserves diagnostics rather than reporting an early success.

Call the following method on the active `ArrivalWizardService` instance, while
it is idle in physical mode and its powered setup has been completed:

```python
preview = service.configure_positional_campaign(
    usb_identity=selected_usb_identity,
    start_joints_rad=reviewed_six_joint_start,
    targets_rad=[reviewed_first_wrist_target, reviewed_second_wrist_target],
    originals=reviewed_original_bytes,
)
```

These variables must come from reviewed retained records and the intended test,
not from this example. Units are radians. Do not substitute guessed zero joint
angles. The execution path obtains fresh feedback and rejects a mismatched start.

`originals` is an exact dictionary mapping these reference names to canonical JSON
**bytes**, not filenames:

| Reference | Required content |
|---|---|
| `native_controller_review_sha256` | Existing typed physical controller-binding original for the selected arm |
| `protocol_review_sha256` | Reviewed protocol original |
| `configuration_sha256` | Reviewed configuration record |
| `workcell_sha256` | Reviewed workcell/clearance record |
| `tool_payload_sha256` | Reviewed tool/payload record |
| `owned_baseline_sha256` | Retained owned baseline record |
| `bounded_motion_risk_sha256` | Explicit attended completion-risk record below |

Runtime and source references are generated by staging. Originals are retained
byte-for-byte and bound by hashes; hashing does not prove their physical truth.
The host adapter must not generate placeholder evidence or automatically mark
physical facts as checked. The current method is a trusted-host attachment API;
an automatic selector of the latest suitable retained hardware records is not
implemented by this change.

The bounded risk record has schema `rocell.attended_bounded_motion_risk.v1` and
exactly six additional boolean fields, all explicitly reviewed as true:
`operator_present`, `entire_accepted_motion_clear`, `no_contact`, `no_added_payload`,
`accepted_goal_may_finish`, `software_cancel_is_not_physical_stop`.
Separate emergency-stop qualification is not required for this bounded attended
profile. USB and AC power alone do not establish safe clearance or stopping ability.

## Running from the wizard

1. Reload the arm page after host attachment. Confirm the displayed unit and both
   absolute targets. Maximum delta is five degrees per leg; absolute wrist targets
   stay within ±10 degrees. Speed setting is 20 and acceleration setting is 1.
2. Complete the operator review and preview the action. This does not open serial.
3. Accept Start once. Its timestamp starts the 30-second campaign lifetime; queue
   delay cannot renew that deadline. Opening serial may cause startup movement.
4. Stay clear and present. The first verified endpoint permits the second command.
   A failed check prevents further submissions; an accepted servo goal may still
   finish after software cancellation or process termination.
5. Review the operation result and per-leg endpoint diagnostics. Encoder-derived
   endpoints are not independent tool-tip XYZ accuracy measurements.
6. Use **Export logs** for the session summary. The standalone verified campaign
   bundle is also written automatically to the assigned export directory.

## Reviewing an export

Each standalone folder is named `campaign-<id>`. It contains
`<campaign-id>-parent-report.json` and only the wrapped original files referenced
by that report: request, stdout, stderr, supervisor record, and any available
launch, claim and trial originals. It does not copy executable packages.

Use `verify_native_retained_export(export_folder, report_filename)` from
`rocell.application.positional_campaign_native_export` to reconstruct and check
the copied bytes without device access. Preserve failed and cancelled runs too.
An export verifies record consistency, not absolute physical positioning.

If export fails, preserve the session originals under the workspace run directory.
Resolve the storage problem and recover the report; do not repeat the movement to
recreate missing output. A repeated Start cannot rearm the consumed campaign.

## Remaining live acceptance

- Attach actual reviewed originals to the active wizard; tests use fixtures.
- Demonstrate this new action with the actual contained child and connected arm.
- Confirm both software endpoint verdicts and inspect the exported raw telemetry.
- Record duration and signed error per leg before considering wider movements or
  parameter changes. This action does not enable unattended operation or contact.
